Security

Vantly Returns · Last updated September 30, 2026

Vantly Returns handles order and customer details on behalf of Shopify merchants. This page describes how we protect that information, how we handle incidents, and how to report a problem. It works together with our Privacy Policy and Data Processing Agreement.

Where data lives

  • The app runs on Render and stores its data in a Neon PostgreSQL database hosted on AWS in the United States (US East).
  • Customer photos are uploaded to the merchant's own Shopify Files, not to our servers.
  • Production and test environments use separate databases. Test work uses test stores and made-up data.

Encryption

  • In transit: every connection uses HTTPS (TLS), including connections between the app and its database.
  • At rest: the database and its backups are encrypted by our database provider (AES-256).
  • API keys merchants connect (for example ShipStation, EasyPost, Katana, Klaviyo, Slack, or webhook secrets) are additionally encrypted with AES-256-GCM using a dedicated key kept outside the database.

Access control

  • Only the people who run Vantly can reach production systems, and only to operate and support the service.
  • Every account with access to production systems or source code (hosting, database, code repository, Shopify Partner account, domain and email) uses a strong unique password and two-step verification.
  • Inside the app, merchants choose what each of their staff can do with roles, and every action on a return is recorded with who did it.

Access logging

  • The app records each time a staff member opens a return, views or searches the returns list, or exports returns. Merchants can see this under Users and roles › Access log. Entries are kept for 12 months.
  • Our hosting provider keeps request logs for the app, used to investigate problems.

Data minimization and retention

  • We only request the Shopify data the app needs to process returns, and use it only for that.
  • Return records are deleted automatically 24 months after the return is closed.
  • When a merchant uninstalls the app, Shopify sends a deletion request and we delete all of that store's data. When a customer asks a merchant to delete their data, we delete that customer's return records.
  • We don't write customer names, emails, phone numbers, or addresses to our logs.

Backups and data loss prevention

  • The database provider keeps continuous, encrypted backups, so the database can be restored to an earlier point in time.
  • All code, database migrations, and hosting configuration are kept in version control, so the service can be rebuilt from scratch.
  • Changes to the database structure are applied through reviewed migrations, never by hand.
  • Data is only exported from the app by the merchant's own staff, and each export is recorded in the access log.

Monitoring

  • An external monitor checks the app every 10 minutes.
  • Failures talking to connected services (for example Slack, Klaviyo, or a merchant's webhook) are recorded on the return and shown to the merchant.

Incident response

If we suspect a security incident, such as unauthorized access to data, a leaked credential, or a vulnerability being exploited, we follow these steps:

  1. Contain: shut off the affected access right away, for example by rotating keys and tokens, revoking sessions, or taking the affected part of the app offline.
  2. Assess: work out what happened, which stores and what data were affected, and when, using the access log and hosting logs.
  3. Notify: if personal data was affected, tell affected merchants and Shopify without undue delay and within 72 hours of confirming it, with what we know and what we're doing. We help merchants meet their own obligations to their customers and regulators.
  4. Fix: close the cause, restore from backup if needed, and confirm the fix.
  5. Learn: write up what happened and what we changed so it doesn't happen again.

Reporting a security issue

If you find a vulnerability or think data may be at risk, email security@vantlyapps.com. We'll confirm we received it and keep you updated. Please don't access other people's data or disrupt the service while testing.
